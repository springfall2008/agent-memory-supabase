# Web UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local web app to browse and search memories and to watch a blackboard board live as a graph, with a click-through drawer that includes the worker's full transcript.

**Architecture:** A new read-only edge function `web-api` (plain HTTP routes over the existing stores, run as the caller through `withMember`). A thin local Deno server (`web/`) adds the member token, proxies an allow-list of `/api/*` routes to that function, serves the static app, and serves worker transcripts from the runner's folder on disk. The browser app is plain JavaScript ES modules with Cytoscape.js vendored; live means polling.

**Tech Stack:** Deno 2 (edge function, local server, tests), `npm:postgres`, vanilla JS ES modules, Cytoscape.js (vendored), Python 3.11+ for the runner change.

**Spec:** `docs/superpowers/specs/2026-11-26-web-ui-design.md`

## Global Constraints

- The web server talks only to Supabase edge functions, never to Postgres.
- Every `web-api` request is authenticated by the bearer token (`resolveCaller`) and runs through `withMember`.
- **Not found** uses the store's existing wording, `Memory <id> not found` (`notFoundMemory`, `pg-store.ts:105`). An unreadable memory, an absent one and a non-UUID id give the same status and the same body once the id is substituted. Tests compare `body.replace(id, '<id>')`.
- Edge CPU per request under about 1 s. Graph polling never constructs the embedder (`LazyEmbedder`).
- Limits: `graph` at most 400 short nodes (`GRAPH_MAX_NODES`) or 100 full; browse at most 400 rows per page (`MAX_BROWSE_LIMIT`); ranked search at most 100 (`MAX_LIMIT`) with no offset.
- Read-only: no route writes. No History tab, no history route, no migration.
- The local server binds `127.0.0.1` and rejects any `Host` other than `localhost` / `127.0.0.1` (any port). It never prints the token or sends it to the browser.
- The poll interval is one named constant, `POLL_MS` in `web/public/poll.js` (default 3000). Task 6 may change it.
- Browser code in `web/public/` is linted and formatted by `deno task check` (`deno fmt` formats `.html` and `.css` too). Use bare `document` / `globalThis`, never `window` (`no-window` lint rule). JSDoc types in `.js` files imported by tests are type-checked, so they must be correct. Pure modules (imported by tests) must not touch the DOM or import the vendored library.
- Python stdlib only for the runner; Python 3.11+. Repo is public: no project refs, company or personal names in committed files; test strings are project-neutral.
- Hosted changes need the person's consent for each run (`supabase functions deploy web-api --use-api` needs `--yes`; `--dry-run` first where it exists). Never deploy without a yes for that run.
- Fixtures and cleanup use fixed or suffixed literal tags (CLAUDE.md), never delete commands built from shell variables.
- Commits only when the person asks. The "Commit" steps below are for when they have.

## Running locally

`.env` holds the **hosted** `AGENT_MEMORY_URL` and token. For a local stack, override in the shell (shell variables win over `--env-file`):

```sh
supabase start && supabase functions serve web-api        # another shell
AGENT_MEMORY_DB_URL=postgresql://postgres:postgres@127.0.0.1:54322/postgres \
  deno run -A scripts/admin.ts issue-token <local member> web-local     # prints a local token once
WEB_API_URL=http://127.0.0.1:54321/functions/v1/web-api AGENT_MEMORY_TOKEN=<local token> deno task web
```

Toy boards run by the runner live on the **hosted** store (`runner/examples/toy.toml` uses scope `agent-memory-tool`), so any check with a real runner needs `web-api` deployed (Task 6).

## Review Focus

Failure modes the spec implies that no single route test would catch, most likely first. Each has a test in the owning task.

1. **Token revoked or expired while the page is open.** Polls return 401. The app shows "Not signed in" and stops polling, rather than drawing an empty board. (Task 12)
2. **A transcript line cut short** (worker killed mid-write) or a non-JSON line. Every parser skips it without throwing. (Task 1, Task 11)
3. **A `By:` label that is not this board's runner label** (`../../etc/passwd`, a glob, another board's label, a 300-character string). The log route refuses it. (Task 9)
4. **A board with only a goal, and a board over 400 nodes.** The first says "No intents yet."; the second says the newest work is not drawn (graph keeps the oldest 400, `pg-store.ts:609`). (Task 12)
5. **A transcript containing non-ASCII text** (an em dash, an emoji). Live following keeps working past it, because offsets are bytes chosen by the server, never computed from JS string length. (Task 9, Task 11)

### Task 4: The `web-api` route handler

**Files:**
- Create: `supabase/functions/_shared/web-api.ts`
- Test: `tests/unit/web-api.test.ts`

**Interfaces:**
- Consumes: `PgMemoryStore.get` and `SearchFilters.touch` (Task 3); `browse`, `search`, `graph`, `listScopes`.
- Produces:
  - `interface WebStore { listScopes(): Promise<ScopeInfo[]>; browse(f: BrowseFilters): Promise<BrowsePage>; search(q: string, mode: SearchMode, f: SearchFilters): Promise<SearchResult[]>; get(id: string): Promise<Memory | null>; graph(f: GraphFilters): Promise<GraphResult>; }`
  - `routeWebApi(req: Request, store: WebStore): Promise<Response>`. The route is the path after the first `/web-api` segment (the platform serves the function at `/functions/v1/web-api/...`). GET only.
  - `GET /scopes` → `{ scopes: ScopeInfo[] }`
  - `GET /memories?q&scope&tags&tags_all&category&limit&offset` → `{ memories: Memory[], hasMore: boolean }`. Empty or absent `q` → `browse`. With `q` → `search(q, 'hybrid', { …, touch: false })`, `hasMore: false`; `offset` with `q` → 400 `offset applies to browsing only`.
  - `GET /memories/:id` → `{ memory: Memory }`, or 404 `{ error: 'Memory <id> not found' }`.
  - `GET /graph?tags_all&scope&detail` → `GraphResult`. `tags_all` required (400 otherwise).
  - `GET /boards` → `{ boards: { scope: string; board: string; state: string | null; goalId: string }[], more: boolean }` from `browse({ tagsAll: ['kind:goal'], limit: 400 })`; `board` from the `board:` tag (goals without one are skipped), `state` from `state:`, `more` = `hasMore`.
  - Query values: `scope`, `tags`, `tags_all` are comma-separated lists. Absent `limit`/`offset` are passed as `undefined` (not `Number(undefined)`); a present non-integer is passed through so `checkLimit` / `checkBrowseLimit` / `checkOffset` reject it. `category` must be one of `MEMORY_CATEGORIES` and `detail` one of `short | full`, else 400.
  - Errors: `StoreError` → 400 `{ error: message }`; unknown route 404, non-GET 405; any other error → 500 `{ error: 'Database error' }` with `console.error`.

- [ ] **Step 2: Run** `deno test -A tests/unit/web-api.test.ts` — FAIL.

### Task 9: Worker log route

**Files:**
- Create: `web/lib/logs.ts`
- Test: `tests/unit/web-logs.test.ts`

**Interfaces:**
- Produces: `serveLog(url: URL, runnerHome: string): Promise<Response>` for `GET /logs/<board>/<label>` with exactly one of `?from=<byte>` (default `0`), `?tail=1`, `?before=<byte>`.
  - Names: `board` matches `^[a-z0-9]+(-[a-z0-9]+)*$`; `label` must equal `board-<board>-<4 lowercase hex>` (the runner's worker label for **this** board, `launch.py:42–44`) or `board-<board>-lead-<4 hex>`. Anything else → 400 `{ error: 'bad name' }`.
  - File: `<runnerHome>/<board>/workers/*-<label>.jsonl`, falling back to `.json`; the newest by mtime if several. `Deno.realPath` of the file must lie inside the real `workers/` folder, so symlinks out are refused.
  - Chunking, cap `LOG_CHUNK_BYTES = 262144`:
    - `from=n`: the bytes from `n`, cut after the last `\n` within the cap.
    - `tail=1`: the last ≤ cap bytes, starting just after a `\n` (or at 0).
    - `before=n`: the ≤ cap bytes ending at `n`, starting just after a `\n`.
    - A single line longer than the cap is returned cut at the cap with `cut: true`, and `next` points past that line's end.
  - Response JSON: `{ found: boolean, running: boolean, size: number, start: number, next: number, text: string, cut: boolean, stderr?: string }`. Offsets are bytes. `text` is the decoded UTF-8 of whole lines, so no chunk splits a character. `stderr` is the `.err` file's first 16 KiB when non-empty.
  - `running`: true only when `<runnerHome>/<board>/state.json` lists a worker with that label **and** the transcript's last complete line is not `"type":"result"`.
  - No file → 200 `{ found: false, running: false, size: 0, start: 0, next: 0, text: '', cut: false }`.

- [ ] **Step 1: Write failing tests** in a temp dir:
  - a transcript is returned whole;
  - `from` returns only later whole lines and `next` advances;
  - a cap cut lands on a line end;
  - `tail` starts on a line boundary, and `before` returns the preceding lines;
  - an over-cap single line gives `cut: true` with `next` past it;
  - **Review Focus 5:** a transcript with `—` and an emoji, followed through `next`, reaches the end with no line lost or duplicated;
  - the `.json` fallback works;
  - `running` is true with a state entry and no result line, false once a result line exists, and false with no entry;
  - an absent file gives `found: false`;
  - **Review Focus 3:** `../../etc/passwd`, `board-x-1234/../../y`, `*`, a 300-character label, a board of `..`, and another board's label `board-other-ab12` on board `toy` all → 400;
  - a symlink inside `workers/` pointing outside is refused.

Forward is accepted only when `chunk.start === buf.next`; otherwise `buf` is returned unchanged. Earlier is accepted only when `chunk.next === buf.start`. The client never computes offsets.
